# 内存回收

> [!info] 目标
> 理解Linux内核的页面回收机制

## 内存回收概述

当系统内存不足时，内核需要回收页面：
- 释放最近最少使用的页面
- 将脏页写回磁盘
- 进程内存与磁盘交换

## 回收触发条件

### 水位线机制

```c
enum zone_watermarks {
    WMARK_MIN,   // 最小水位线
    WMARK_LOW,   // 低水位线
    WMARK_HIGH,  // 高水位线
};

// 触发条件
free_pages < WMARK_LOW  → 启动kswapd后台回收
free_pages < WMARK_MIN  → 直接回收（阻塞）
free_pages > WMARK_HIGH → 停止kswapd
```

### 内存压力状态

```
┌─────────────────┐
│    WMARK_HIGH   │ ←─ kswapd停止
├─────────────────┤
│                 │
├─────────────────┤
│    WMARK_LOW    │ ←─ kswapd启动
├─────────────────┤
│                 │
├─────────────────┤
│    WMARK_MIN    │ ←─ 直接回收
├─────────────────┤
│                 │
└─────────────────┘
      内存减少 →
```

## 页面分类

### 可回收页面

| 类型 | 说明 | 回收方式 |
|------|------|----------|
| 干净的文件页 | 内容与磁盘一致 | 直接丢弃 |
| 脏的文件页 | 内容已修改 | 写回磁盘后丢弃 |
| 匿名页 | 无文件关联 | 写入swap |

### 不可回收页面

- 锁定的页面（mlock）
- 内核使用的页面
- 共享内存页面（特定情况）

## LRU链表

Linux使用多个LRU链表管理页面：

```c
// include/linux/mmzone.h
enum lru_list {
    LRU_INACTIVE_ANON,    // 不活跃匿名页
    LRU_ACTIVE_ANON,      // 活跃匿名页
    LRU_INACTIVE_FILE,    // 不活跃文件页
    LRU_ACTIVE_FILE,      // 活跃文件页
    LRU_UNEVICTABLE,      // 不可回收页
    NR_LRU_LISTS
};
```

### LRU结构

```
                    活跃链表                         不活跃链表
匿名页: LRU_ACTIVE_ANON  ←────────────→  LRU_INACTIVE_ANON
                          提升降级
文件页: LRU_ACTIVE_FILE  ←────────────→  LRU_INACTIVE_FILE
                          提升降级

         │                              │
         │ 页面被访问                    │ 最近未访问
         ▼                              ▼
      移到头部                        移到尾部
      (热页面)                        (冷页面，优先回收)
```

### 页面状态转换

```
新分配页面
     │
     ▼
┌──────────────┐
│ 加入不活跃    │
│ 链表头部      │
└──────┬───────┘
       │
       │ 被访问
       ▼
┌──────────────┐
│ 提升到活跃    │
│ 链表头部      │
└──────┬───────┘
       │
       │ 长期未访问
       ▼
┌──────────────┐
│ 降级到不活跃  │
│ 链表尾部      │
└──────┬───────┘
       │
       │ 仍不活跃
       ▼
┌──────────────┐
│   回收页面    │
└──────────────┘
```

## kswapd守护进程

### 工作流程

```c
// mm/vmscan.c
static int kswapd(void *p)
{
    struct pglist_data *pgdat = p;

    for (;;) {
        // 等待唤醒
        wait_event_interruptible(pgdat->kswapd_wait,
                                 kthread_should_stop() ||
                                 pgdat->kswapd_order > 0);

        // 回收页面直到水位高于high
        balance_pgdat(pgdat, order, classzone_idx);
    }
    return 0;
}
```

### 平衡目标

```
kswapd回收目标：
1. 使每个zone的空闲页面 >= WMARK_HIGH
2. 保持active/inactive链表平衡
3. 优先回收文件页（避免swap）
```

## 直接回收

当内存严重不足时，进程直接执行回收：

```c
// mm/vmscan.c
static unsigned long do_try_to_free_pages(struct zonelist *zonelist,
                                          struct scan_control *sc)
{
    // 1. 尝试回收页面
    shrink_zones(zonelist, sc);

    // 2. 如果仍不足，触发OOM
    if (!sc->nr_reclaimed) {
        out_of_memory(&(sc->target_mem_cgroup), gfp_mask, order);
    }

    return sc->nr_reclaimed;
}
```

## 页面回收算法

### 双时钟算法

```
活跃链表:    [H───P───P───P───T] (refault检测)
              ↑   ↑
              头  尾

不活跃链表:  [H───P───P───P───T]
              ↑   ↑
              头  尾 (优先回收)

P = 页面
H = 链表头部 (最近使用)
T = 链表尾部 (最少使用)
```

### Refault距离

```c
// 页面被回收后又被访问的距离
refault_distance = current_time - eviction_time

// 如果距离 < 不活跃链表大小
// → 页面在回收前刚刚进入不活跃区
// → 说明它实际上是被频繁访问的
// → 应该直接提升到活跃链表
```

## Swap机制

### Swap使用场景

```c
// 匿名页面回收时写入swap
static int __remove_mapping(struct address_space *mapping,
                            struct page *page)
{
    if (PageSwapCache(page)) {
        // 已在swap中
        swapcache_free(page);
    } else if (PageDirty(page)) {
        // 写入swap
        add_to_swap(page);
    }
}
```

### Swap优先级

```bash
# 查看swap使用
cat /proc/swaps

# 设置swappiness (0-100)
# 值越大越倾向于使用swap
cat /proc/sys/vm/swappiness

# 默认值通常为60
# 服务器建议设为10-30
```

## 调优参数

```bash
# 主要调优参数
/proc/sys/vm/swappiness        # swap倾向
/proc/sys/vm/vfs_cache_pressure # 回收inode/dentry缓存的倾向
/proc/sys/vm/min_free_kbytes   # 最小保留内存
/proc/sys/vm/dirty_ratio       # 脏页比例上限
/proc/sys/vm/dirty_background_ratio # 后台写回触发比例

# 查看当前设置
sysctl -a | grep vm
```
