# 页面分配器

> [!info] 目标
> 理解Linux内核的伙伴系统（Buddy System）页面分配机制

## 伙伴系统概述

伙伴系统是Linux物理页面分配的核心算法：
- 按2的幂次方分配页面
- 支持快速合并，减少碎片
- 分配/释放时间复杂度O(1)

## 伙伴系统原理

### 空闲区域组织

```
Order 0 (1页 = 4KB):  [P1] [P2] [P3] [P4] [P5] [P6] [P7] [P8]
Order 1 (2页 = 8KB):  [P1-P2] [P3-P4] [P5-P6] [P7-P8]
Order 2 (4页 = 16KB): [P1-P4] [P5-P8]
Order 3 (8页 = 32KB): [P1-P8]
```

### 分配示例

```
初始状态：空闲8页

请求2页：
  Order 2不可用 → 拆分Order 3
  得到两个Order 2块：[P1-P4] [P5-P8]
  [P1-P4]继续拆分为两个Order 1：[P1-P2] [P3-P4]
  分配[P1-P2]，剩余[P3-P4]和[P5-P8]

释放[P1-P2]：
  检查伙伴[P3-P4]是否空闲
  是 → 合并为Order 2的[P1-P4]
  继续检查[P5-P8]是否空闲
  是 → 合并为Order 3的[P1-P8]
```

## 数据结构

### free_area

```c
struct free_area {
    struct list_head free_list[MIGRATE_TYPES]; // 空闲页链表
    unsigned long nr_free;    // 空闲块数量
};

// MIGRATE_TYPES: 迁移类型
enum migratetype {
    MIGRATE_UNMOVABLE,     // 不可移动
    MIGRATE_MOVABLE,       // 可移动
    MIGRATE_RECLAIMABLE,   // 可回收
    MIGRATE_PCPTYPES,      // Per-CPU类型数量
    MIGRATE_HIGHATOMIC = MIGRATE_PCPTYPES,
    MIGRATE_CMA,           // 连续内存分配
    MIGRATE_ISOLATE,
    MIGRATE_TYPES
};
```

### zone中的伙伴系统

```c
struct zone {
    // ...
    struct free_area free_area[MAX_ORDER];  // 11个order
    // ...
};

#define MAX_ORDER 11  // 最大order，可分配2^10=1024页=4MB
```

## 分配函数

### 核心API

```c
#include <linux/gfp.h>

// 分配单个页面
struct page *alloc_page(gfp_t gfp_mask);
struct page *alloc_pages(gfp_t gfp_mask, unsigned int order);

// 获取虚拟地址
void *page_address(const struct page *page);

// 分配并获取虚拟地址
unsigned long __get_free_pages(gfp_t gfp_mask, unsigned int order);
unsigned long __get_free_page(gfp_t gfp_mask);
unsigned long get_zeroed_page(gfp_t gfp_mask);  // 零初始化

// 释放
void __free_pages(struct page *page, unsigned int order);
void free_pages(unsigned long addr, unsigned int order);
```

### GFP标志

```c
// 区域修饰符
#define __GFP_DMA       0x200u
#define __GFP_HIGHMEM   0x400u
#define __GFP_DMA32     0x800u

// 移动性修饰符
#define __GFP_MOVABLE   0x100000u
#define __GFP_RECLAIMABLE 0x10000u

// 水位修饰符
#define __GFP_HIGH      0x20u    // 高优先级
#define __GFP_ATOMIC    0x80000u // 原子分配，不能睡眠
#define __GFP_NOMEMALLOC 0x10000u

// 常用组合
#define GFP_KERNEL  (GFP_NOWAIT | __GFP_NOWARN | __GFP_NORETRY)
#define GFP_ATOMIC  (__GFP_HIGH | __GFP_ATOMIC | __GFP_KSWAPD_RECLAIM)
#define GFP_USER    (GFP_KERNEL | __GFP_RECLAIMABLE)
#define GFP_DMA     __GFP_DMA
#define GFP_DMA32   __GFP_DMA32
```

### 分配示例

```c
// 分配一个页面
struct page *page = alloc_page(GFP_KERNEL);
if (!page)
    return -ENOMEM;

void *addr = page_address(page);
// 使用addr...

__free_page(page);

// 分配4个连续页面
struct page *pages = alloc_pages(GFP_KERNEL, 2);  // 2^2 = 4页
if (!pages)
    return -ENOMEM;

// 或直接获取地址
unsigned long addr = __get_free_pages(GFP_KERNEL, 2);
if (!addr)
    return -ENOMEM;

free_pages(addr, 2);
```

## Per-CPU页面缓存

为提高性能，每个CPU维护一个页面缓存：

```c
struct per_cpu_pages {
    int count;          // 页面数量
    int high;           // 高水位，超过则释放
    int batch;          // 一次添加/释放的页面数

    struct list_head lists[MIGRATE_PCPTYPES]; // 页面链表
};

struct per_cpu_pageset {
    struct per_cpu_pages pcp;
    // ...
};
```

### PCP工作流程

```
分配单页：
  1. 从当前CPU的PCP中取
  2. PCP为空 → 从伙伴系统批量获取batch个页面
  3. 返回一个页面

释放单页：
  1. 放入当前CPU的PCP
  2. PCP页面数超过high → 释放batch个页面回伙伴系统
```

## 分配路径

```
alloc_pages(gfp_mask, order)
        │
        ▼
┌─────────────────┐
│ 检查order范围   │

└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 选择Zone        │
│ 根据gfp_mask   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ order == 0?     │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
从PCP获取  从伙伴系统获取
    │         │
    │         ▼
    │    ┌─────────────┐
    │    │ 当前order有 │
    │    │ 空闲块?     │
    │    └──────┬──────┘
    │           │
    │      ┌────┴────┐
    │      │是       │否
    │      ▼         ▼

    │                  │

              │

```

## 碎片处理

### 外部碎片
- 问题：物理内存不连续
- 解决：伙伴系统、内存迁移

### 内部碎片
- 问题：分配大于实际需求
- 解决：Slab分配器处理小对象

### 内存迁移

```c
// 迁移类型
MIGRATE_UNMOVABLE   // 内核分配，不可移动
MIGRATE_MOVABLE     // 用户页面，可移动
MIGRATE_RECLAIMABLE // 可回收页面
MIGRATE_CMA         // 连续内存分配区
```
