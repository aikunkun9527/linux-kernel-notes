# 异常处理

> [!info] 目标
> 理解CPU异常的类型、处理流程和内核实现

## 异常分类

### 三种异常类型

| 类型 | 原因 | 返回行为 | 示例 |
|------|------|----------|------|
| **故障（Fault）** | 可恢复的错误 | 返回引起故障的指令 | 缺页异常 |
| **陷阱（Trap）** | 有意的异常 | 返回下一条指令 | 断点、系统调用 |
| **终止（Abort）** | 严重错误 | 无法继续执行 | 双重故障 |

### 异常处理流程

```
异常发生
    │
    ▼
┌─────────────────┐
│ CPU保存上下文   │
│ (栈帧)          │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 查IDT获取处理   │
│ 程序地址        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 特权级切换      │
│ (如需要)        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 执行异常处理    │
│ do_XXX()        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ iret返回        │
└─────────────────┘
```

## 缺页异常（#PF）

### 错误码格式

```
┌───┬───┬───┬───┬───────────────────────────┐
│ 0 │ 0 │ 0 │ I │        保留               │
├───┼───┼───┼───┼───────────────────────────┤
│ P │ W │ U │ R │          保留              │
│   │ / │ / │ S │                           │
│   │ R │ S │ V │                           │
└───┴───┴───┴───┴───────────────────────────┘
  0   1   2   3   4-31

P (bit 0):  0=页面不存在, 1=保护违规
W/R (bit 1): 0=读, 1=写
U/S (bit 2): 0=内核态, 1=用户态
RSV (bit 3): 保留位错误
I/D (bit 4): 0=数据, 1=指令
```

### 缺页处理流程

```c
// arch/x86/mm/fault.c
void do_page_fault(struct pt_regs *regs, unsigned long error_code)
{
    unsigned long address = read_cr2();  // 获取故障地址

    // 1. 查找VMA
    vma = find_vma(mm, address);

    // 2. 判断缺页原因
    if (!(vma->vm_flags & VM_WRITE) && (error_code & X86_PF_WRITE)) {
        // 写只读区域
        bad_area_access_error(regs, error_code, address);
        return;
    }

    // 3. 处理缺页
    if (!(vma->vm_flags & VM_EXEC) && (error_code & X86_PF_INSTR)) {
        // 执行不可执行区域
        bad_area_access_error(regs, error_code, address);
        return;
    }

    // 4. 分配页面或处理COW
    handle_mm_fault(vma, address, flags);
}
```

### 缺页类型

```
缺页异常
    │
    ├─ 页面不存在
    │   ├─ 首次访问（分配新页）
    │   ├─ 页面被换出（从swap读入）
    │   └─ 文件映射（从文件读入）
    │
    ├─ 权限错误
    │   ├─ 写只读页（COW）
    │   ├─ 用户访问内核页
    │   └─ 执行不可执行页（NX）
    │
    └─ 其他
        └─ 保留位错误
```

## 一般保护异常（#GP）

### 常见原因

```c
// 触发#GP的情况
1. 访问不存在的段
2. 段选择子超出GDT/LDT边界
3. 切换到忙碌的任务
4. 加载无效的段选择子
5. 访问超出段边界
6. 用户态访问内核内存
7. 写只读内存
```

### 处理

```c
// arch/x86/kernel/traps.c
static void do_general_protection(struct pt_regs *regs, long error_code)
{
    // 检查是否在用户态
    if (user_mode(regs)) {
        // 用户态GP → 发送SIGSEGV
        force_sig(SIGSEGV);
        return;
    }

    // 内核态GP → 严重错误
    if (fixup_exception(regs)) {
        // 有异常表修复
        return;
    }

    // 无法修复 → panic
    die("general protection fault", regs, error_code);
}
```

## 除法错误异常（#DE）

```c
// 触发条件
1. DIV/IDIV指令除数为0
2. 除法结果超出目标寄存器范围

// 处理
static void do_divide_error(struct pt_regs *regs, long error_code)
{
    // 用户态 → SIGFPE
    if (user_mode(regs)) {
        force_sig(SIGFPE);
        return;
    }

    // 内核态 → 检查修复
    if (fixup_exception(regs))
        return;

    die("divide error", regs, error_code);
}
```

## 双重故障（#DF）

```c
// 发生条件：处理异常时又发生异常，且无法恢复
// 通常意味着严重的系统错误

static void do_double_fault(struct pt_regs *regs, long error_code)
{
    // 双重故障无法恢复
    panic("Double fault at %pS\n", (void *)regs->ip);
}
```

## 调试异常（#DB）

### 触发条件

```c
1. 指令断点（DR0-DR3）
2. 数据断点（DR0-DR3 + DR7）
3. 单步执行（TF标志）
4. 任务切换
5. 进入/退出电源管理
```

### 处理

```c
static void do_debug(struct pt_regs *regs, unsigned long dr6)
{
    // 检查断点类型
    if (dr6 & DR_TRAP0)  // DR0断点
        ...
    if (dr6 & DR_TRAP1)  // DR1断点
        ...
    if (dr6 & DR_STEP)   // 单步执行
        ...

    // 发送SIGTRAP给进程
    force_sig(SIGTRAP);
}
```

## 异常修复表

内核使用异常修复表处理某些可恢复的异常：

```c
// arch/x86/include/asm/asm.h
#define _ASM_EXTABLE_HANDLE(from, to, handler) \
    .pushsection "__ex_table", "a" ;           \
    .balign 4 ;                                \
    .long (from) - . ;                         \
    .long (to) - . ;                           \
    .popsection

// 使用示例
// 如果访问用户地址出错，跳转到修复代码
copy_user:
    rep movsb
    ...
    .section __ex_table, "a"
    .quad copy_user, copy_user_error
    .previous
```
