# Linux系统调用

> [!info] 概述
> 系统调用是用户态程序与内核交互的唯一合法接口，是操作系统的"大门"

## 🧠 核心概念

### 什么是系统调用

- **定义**：用户程序请求内核服务的API接口
- **作用**：提供安全、可控的硬件资源访问
- **特权级切换**：从Ring 3（用户态）到Ring 0（内核态）

### 系统调用 vs 函数调用

| 特性 | 系统调用 | 函数调用 |
|------|----------|----------|
| 特权级 | 切换到内核态 | 不切换 |
| 开销 | 较大（上下文切换） | 很小 |
| 地址空间 | 切换到内核空间 | 同一空间 |
| 调用方式 | syscall/int 0x80 | call指令 |
| 安全性 | 受内核控制 | 不受控 |

### 常用系统调用速查

| 类别 | 系统调用 | 功能 | 关联内核函数 |
|------|----------|------|--------------|
| 进程 | `fork()` | 创建子进程 | `sys_clone` |
| 进程 | `execve()` | 执行程序 | `sys_execve` |
| 进程 | `exit()` | 终止进程 | `sys_exit` |
| 文件 | `open()` | 打开文件 | `sys_openat` |
| 文件 | `read()` | 读文件 | `sys_read` |
| 文件 | `write()` | 写文件 | `sys_write` |
| 内存 | `mmap()` | 内存映射 | `sys_mmap` |
| 内存 | `brk()` | 调整堆 | `sys_brk` |

## 系统调用流程详解

```
用户程序调用 write(fd, buf, count)
           │
           ▼
┌─────────────────────────────────────┐
│  glibc封装                           │
│  - 设置系统调用号到rax               │
│  - 设置参数到rdi/rsi/rdx             │
│  - 执行syscall指令                   │
└──────────────────┬──────────────────┘
                   │
                   │ syscall指令
                   ▼
┌─────────────────────────────────────┐
│  CPU硬件处理                         │
│  - 保存用户态RIP到RCX                │
│  - 保存RFLAGS到R11                   │
│  - 从MSR加载内核CS:RIP               │
│  - 切换到内核栈                      │
│  - 特权级从3变为0                    │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│  entry_SYSCALL_64                    │
│  - swapgs（切换GS基址）              │
│  - 保存用户态寄存器到pt_regs         │
│  - 调用sys_call_table[rax]           │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│  sys_write()                         │
│  - 检查文件描述符                    │
│  - 检查用户空间缓冲区                │
│  - 调用VFS写入                       │
│  - 返回结果                          │
└──────────────────┬──────────────────┘
                   │
                   │ sysret/iret
                   ▼
              返回用户程序
```

## 参数传递机制

### x86_64寄存器约定

```c
// 系统调用参数传递
// rax = 系统调用号
// rdi = 参数1, rsi = 参数2, rdx = 参数3
// r10 = 参数4, r8  = 参数5, r9  = 参数6
// 返回值在rax中

// 示例：write(2, buf, 100)的系统调用
// rax = 1 (__NR_write)
// rdi = 2  (fd)
// rsi = buf (buffer地址)
// rdx = 100 (count)
```

### 系统调用号定义

```c
// include/uapi/asm-generic/unistd.h
#define __NR_io_setup          0
#define __NR_io_destroy        1
#define __NR_io_submit         2
#define __NR_io_cancel         3
#define __NR_io_getevents      4
#define __NR_setxattr          5
// ...
#define __NR_read             63
#define __NR_write            64
#define __NR_openat          257
// ...

// x86_64: arch/x86/entry/syscalls/syscall_64.tbl
// 64-bit system call numbers:
//   0    common  read            sys_read
//   1    common  write           sys_write
```

## 系统调用开销

```
系统调用开销组成：

1. 用户态→内核态切换
   ├── 保存用户态寄存器
   ├── 加载内核栈
   └── 特权级切换
   约 100-200 CPU周期

2. 内核态处理
   ├── 参数检查和复制
   ├── 实际操作
   └── 结果返回

3. 内核态→用户态返回
   ├── 恢复用户态寄存器
   ├── 切换回用户栈
   └── 特权级切换
   约 100-200 CPU周期

总计：约 200-500 纳秒（现代CPU）
```

## 查看系统调用

### 使用strace

```bash
# 跟踪程序的所有系统调用
strace ./program

# 只跟踪特定系统调用
strace -e trace=read,write ./program

# 统计系统调用
strace -c ./program

# 跟踪正在运行的进程
strace -p <PID>
```

### 使用/proc

```bash
# 查看进程的系统调用
cat /proc/<PID>/syscall

# 查看进程打开的文件
ls -la /proc/<PID>/fd/
```

```

├── syscalls.h              # 系统调用声明
└── syscall.h               # 系统调用相关定义

include/uapi/asm-generic/
└── unistd.h                # 系统调用号定义
```
