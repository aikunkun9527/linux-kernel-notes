## 实验六：内存回收机制

### 观察结果

#### 6.1 内存回收机制概述

Linux内核通过两种方式回收内存：
1. **后台回收(kswapd)**: 空闲内存低于low水位时触发，异步回收
2. **直接回收(direct reclaim)**: 空闲内存低于min水位时触发，同步回收

#### 6.2 Zone水位线分析

```
Zone Normal水位线:
  min:  5,345 页 (20.9 MB)
  low:  6,297 页 (24.6 MB)
  high: 7,249 页 (28.3 MB)

水位线作用:
  - free < high: kswapd可能停止
  - free < low:  kswapd开始后台回收
  - free < min:  触发直接回收（阻塞分配）
```

#### 6.3 内存压力测试

**测试条件**: 分配1536MB内存

| 指标 | 分配前 | 分配后 | 变化 |
|------|--------|--------|------|
| MemFree | 1,061 MB | 101 MB | -960 MB |
| MemAvailable | 2,313 MB | 829 MB | -1,484 MB |
| SwapFree | 3,555 MB | 3,495 MB | -60 MB |
| free页数 | 6,354 | 3,414 | -2,940 |

**内存回收统计：**
```
kswapd扫描页面: 148,791
kswapd回收页面: 126,749
页面换入(swap in): 62
页面换出(swap out): 15,086
```

**分析：**
- kswapd回收效率: 126,749 / 148,791 = 85.2%
- 页面换出: 15,086页 ≈ 59MB被换出到swap
- 系统通过回收页缓存和匿名页来释放内存

#### 6.6 内存回收工作流程

```
┌─────────────────────────────────────────────────────────────┐
│                     内存分配请求                              │
└─────────────────────┬───────────────────────────────────────┘
                      │
                      ▼
              ┌───────────────┐
              │ 检查空闲内存   │
              └───────┬───────┘
                      │
          ┌───────────┼───────────┐
          │           │           │
    free≥high    low≤free<high  free<low
          │           │           │
          ▼           ▼           ▼
      直接分配    监控状态    kswapd开始
                              后台回收
                                  │
                                  ▼
                          ┌──────────────┐
                          │ free<min?    │
                          └──────┬───────┘
                                 │
                    ┌────────────┼────────────┐
                    │            │            │
                  否            是           │
                    │            │            │
                    ▼            ▼            │
              继续后台回收   直接回收    ──────┘
              (kswapd)     (阻塞分配)
```

### 遇到的问题与解决

1. **vmstat字段名错误**
   - 问题: 使用了`pgscan_kswapd_total`导致读取失败
   - 解决: 修正为正确的字段名`pgscan_kswapd`

2. **kswapd tracepoints无事件**
   - 原因: 内存充足时kswapd不会被唤醒
   - 解决: 通过内存压力测试触发kswapd活动

### 思考题

1. **为什么需要水位线机制？**
   - 提前回收：在内存耗尽前开始回收，避免直接回收的性能影响
   - 平衡回收：kswapd异步回收，不阻塞进程
   - 防止OOM：保证内存分配成功率

2. **kswapd vs 直接回收的性能差异？**
   - kswapd: 后台异步执行，不阻塞进程
   - 直接回收: 同步执行，阻塞分配进程，性能影响大

3. **swappiness参数的作用？**
   - 值越大，越积极使用swap回收匿名页
   - 值越小，优先回收页缓存
   - 默认60是平衡值

### 关键发现

1. **kswapd回收效率高**: 85-91%的扫描页面被成功回收
2. **水位线动态调整**: 根据zone大小自动计算
3. **swap使用保守**: 系统优先回收页缓存，较少使用swap
